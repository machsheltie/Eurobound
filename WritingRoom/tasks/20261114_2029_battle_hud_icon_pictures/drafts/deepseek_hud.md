# Deepseek — Battle HUD status icons (slice 2 of 3)

Eight statuses: space_cake_gamble, canal_confusion, tunnel_confusion, tunnel_vision, sloppy, confused, stun, tourist_trap_victim.

Look: one chunky 3D object on a round badge, readable as a silhouette at 28 px, no lettering anywhere. All rows PROPOSED until the author approves the list.

**Where these ids live:** none of my eight has an entry in `game/assets/data/skills/status_effects.json` (that file holds the field/city statuses). All eight are battle-side ids; seven are on `game/battle/battle_core.gd:17` `NEGATIVE`, and `tunnel_vision` is the one buff. So there is no `cues` block to honour and no approved object to inherit: the icon file name is the id (`<status id>.png`). Display names are taken verbatim from the master list in `design/mechanics/Battle/status_effects.md` — **Stun**, not "Stunned" (the battle log says "is stunned"; the status name is Stun).

**Border rule I used (proposal, one line):** red for a status that hurts inside the fight, orange for a status that hurts outside it (map, money). GDD 309 allows either for debuffs, so this costs nothing and gives 28 px a second read. It conflicts with Kimi's slice, which files field statuses red — flagged below.

## Notes for review

1. **No lettering, checked row by row.** The 8-ball has no 8 on it. The postcards are blank on the back and the fronts are colour bands, not print. The phone screen is a flat field, never digits. The arrow is an arrow.
2. **28 px collision check.** Sphere: the 8-ball is the only black object in the set, the cotton ball the only white round one — separated by value, not shape. Cube: confused is the only cube. Three confusion-family silhouettes (fan / U-arrow / cube) share no edge. Two rectangles are left: the phone (upright, antenna) and the flashlight (horizontal, beam) — different axes.
3. **Watch for two neighbours I can't see yet.** `confused`'s blindfold is a mask shape and Mistral's `embarrassed` is a pulsing blush — a cheek is not a mask, but if his blush reads as any sort of face shape at 28 px, mine goes. `tourist_trap_victim`'s fanny pack is a money container: if Mistral draws `broke_af` as a wallet, the pouch-and-strap still reads apart from a flat fold, but it's the closest pair in the set. Both are his call, not mine.
4. **Two production risks, both resolvable.** The 8-ball is a sphere on a round badge (a smaller circle inside a circle); the square window and its rim highlight break it — if it still reads as a donut at 28 px, invert it: same ball, window enlarged to a third of the width. The postcard fan is my only soft-edged silhouette and the likeliest to fail the readability gate; the runner-up, if it fails, is a single chunky brick that flips over to show an identical face (cheap, era-proof, and it makes the same "every street is the same street" joke).
5. **Border rule conflict with Kimi, one line to settle:** she files field statuses red (Windmill Grist, Contact High); I file them orange and keep red for in-fight damage. Either is legal under GDD 309. Mine buys a second read at 28 px; hers is simpler to write into the GDD. Pick one and the integrator applies it to both slices. If the author wants a single debuff colour, everything in my slice goes red except tunnel_vision.

**Reviewer:** Mistral — 28 px readability (especially the sphere and the fan), the border rule in note 5, and collisions with `broke_af`, `embarrassed` and the four action-type icons. Kimi second read on the last column.
